# Execution Plan: Execution plan browser inspired by todo UX

Date: 2026-09-05

## Status

Ready for completion

## Outcome

Provide /continuity plans [query] in trusted TUI repositories to fuzzy-search existing active/completed execution plans, view Markdown, and prepare Work/Refine drafts for explicit submission without creating parallel task state or changing plan/binding/completion authority.

## Authority And Context

- User supplied /storage/emulated/0/Download/todos.ts and explicitly selected the recommended execution-plan UX adaptation rather than an independent todo subsystem.
- AGENTS.md; docs/ARCHITECTURE.md; README.md; proof/ACCEPTANCE.md.
- Installed Pi extension/TUI documentation and locked Pi 0.84.1 public declarations; reference file is behavioral inspiration, not code copied into the package.

## Scope

In scope:

- Read-only bounded discovery and fresh detail reads under docs/plans/active and docs/plans/completed using existing plan path/identity rules.
- TUI search/filter, keyboard navigation, Markdown detail with scrolling, and reviewable Work/Refine editor drafts.
- Tests for file safety, stale/deleted plans, editor preservation, mode/trust/session boundaries, UI rendering, and existing authority remaining unchanged.
- README, architecture/acceptance mapping, focused proof and required runtime/premerge validation.
- Pin the existing host-provided pi-tui API as a dev-only dependency if needed for strict typecheck and native ESM tests; no runtime dependency additions.

Out of scope:

- Independent todo storage, tags/assignments/locks, automatic GC, plan editing/deletion/finalization, automatic binding, or synthetic user submission.
- Memory/SQLite/receipt/checkpoint authority changes, provider calls, host changes, installation/deployment, commits or publishing.
- Unrelated pre-existing changes and historical release archives.

## Constraints

- No UI access or discovery from this command in RPC/JSON/print; require current project trust and a canonical repository root.
- Empty discovery must create no directories; reject unsafe paths/symlinks/nonregular/oversized files and bound catalog work.
- Plan content/status is display data, not proof of completion or permission; completed plans cannot be resumed by Work.
- Re-read selected plan before drafting, refuse stale identity/digest, preserve any editor text without silently overwriting it.
- Use strict ESM, Node built-ins, repository layers and host Pi TUI primitives.

## Approach

- Establish read-only catalog/detail behavior test-first with filesystem fixtures.
- Implement and test search/detail UI and guarded command draft orchestration.
- Document the command and authority boundaries; review the diff and run required gates.
- Record actual verification/results, finalize the task plan with receipt-bound validation, and report deployment limits.

## Risks And Recovery

- Filesystem drift, unsafe aliases, malformed metadata or large files: fail bounded and visibly, do not write or automatically retry a plan mutation.
- Session/tree replacement while a browser is open: discard obsolete interaction and never update a replacement editor.
- UI integration may differ from mocks: verify a fresh isolated Pi load and component behavior on the supported API; label unobserved live-terminal UX honestly.
- Rollback is a focused revert of this feature's source/docs/dev dependency changes; no persistent store or plan migration is introduced.
- Generated dist/.test-build contain prior build output and may be regenerated by gates; pre-existing release ZIPs remain untouched.
